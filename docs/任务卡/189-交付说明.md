# 卡 189 交付说明：媒体会话可行性探针（仅调试版）

**分支**：`card/TaoSheng-189-media-probe`（不合入 main，验证结束即丢弃）
**Base**：372d2054（远端 main，PR #4 合并提交）

## 做了什么

- `app/src/debug/AndroidManifest.xml`：声明 `app.resound.probe.MediaProbeService`（`BIND_NOTIFICATION_LISTENER_SERVICE` + NotificationListenerService intent-filter）。已验证与主清单正常合并：debug 包合并清单含该服务，release 包不含。
- `app/src/debug/java/app/resound/probe/MediaProbeService.kt`：`NotificationListenerService` 探针。`onListenerConnected` 取 `MediaSessionManager`，`getActiveSessions` 对每个控制器打一行 `snapshot`；注册 `addOnActiveSessionsChangedListener`（列表变化时先注销旧回调再重打 snapshot）与每个控制器的 `registerCallback`（`state` / `meta` / `gone`）。生命周期打 `created` / `connected` / `disconnected` / `destroyed`（带 `at=` 毫秒时间戳）。未授权时 `getActiveSessions` 抛 SecurityException 直接崩——崩溃本身就是结论，属探针语义。

- `./gradlew -PskipSigningSecrets=true :app:assembleRelease -q` => exit 0

## 真机验收（由负责人执行）

1. 授权通知使用权（无界面引导，用 adb），然后看日志：

   ```
   adb shell cmd notification allow_listener app.resound/app.resound.probe.MediaProbeService
   adb logcat -s mediaprobe
   ```

2. 日志格式（每行一个事件，缺失字段写 `null`）：

   ```
   <事件> pkg=<包名> state=<PlaybackState.state 整数或 null> title=<标题> artist=<艺术家> album=<专辑> subtitle=<副标题> duration=<时长毫秒> pos=<播放位置毫秒>
   ```

   事件含义：`snapshot`＝当前活跃会话清单（连接后及列表变化时）；`state`＝播放状态变化（`state` 列：2=PLAYING、3=PAUSED，其余见 `PlaybackState.State`）；`meta`＝元数据变化；`gone`＝会话销毁；`created`/`connected`/`disconnected`/`destroyed`＝服务生命周期，带 `at=` 毫秒时间戳。

3. 判定点：a) 对照 `adb shell dumpsys media_session`，看包名/标题/副标题/进度是否一致（B站重点看副标题是否「自动连播」而非 UP 主）；b) 熄屏静置 2 小时后回看：`connected` 之后有无 `disconnected`/`destroyed`，播放/暂停是否仍产生 `state` 行。

## 遗留问题

- `duration` 用 `keySet().contains` 判缺失（`getLong` 对缺失键返回 0，无法区分「时长 0」与「没这字段」），是读值方式差异，不是 fallback。
- 若澎湃 OS 熄屏期间杀掉服务（日志只见 `destroyed`，之后无 `connected`），结论是「需自启动白名单或前台服务保活」，属第 3 步决策，不在本卡处理。
