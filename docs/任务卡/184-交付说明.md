# 184 整理提示词加入外放提示 · 交付说明

## 做了什么

普通整理与重新整理的转写提示里，对扬声器外放时长 ≥ 3000 毫秒的手机麦克风片段（`sourceId = 'mic'`）加外放标注，让大模型知道「节目里的话不是负责人说的」：

1. **core `SituationPrompt`**（`shared/src/commonMain/kotlin/app/resound/digest/core/SituationPrompt.kt`）
   - 构造新增 `playback: Map<Long, Long>`（片段编号 → 外放毫秒数，默认空）；
   - 开关关闭（或 lookup 为空）时，外放片段的情境行只有 `【外放：有】`，其余输出逐字不变；
   - 开关打开且 lookup 非空时，情境行在原有各项之后追加 `外放：来源未知`（如 `【当时在：公司｜周围：雨｜外放：来源未知】`，原有项全空时为 `【外放：来源未知】`）；
   - 新增常量 `PLAYBACK_RULE`，`system()` 在本批任一片段外放 ≥ 3000 毫秒时追加（开关打开时追加在 `RULE` 之后）；`RULE` 原文一字未改；
   - 合并路径（`merge`）不出外放项。
2. **安卓包装 `SituationPrompt`**（`app/src/main/java/app/resound/digest/SituationPrompt.kt`）：透传 `playback`，companion 透出 `PLAYBACK_RULE`。
3. **`TranscribeDao`**（`shared/src/commonMain/kotlin/app/resound/data/TranscribeDao.kt`）：新增 `playbackMillis(ids)` 查询（参考 `unseparated(ids)` 写法），只按 `sourceId = 'mic'` 过滤，不按毫秒数过滤（阈值判定收在 `SituationPrompt` 一处）；返回新增 POJO `SegmentPlayback(id, playbackMillis)`。没动数据库版本、没加列（并行卡 185b 在改 `CaptureDatabase.kt`，本卡未碰）。
4. **`DigestRunner`**（`app/src/main/java/app/resound/digest/DigestRunner.kt`）：新增构造参数 `playbackMillis`（与现有 `unseparated` 同模式的回调注入），整理构造 `SituationPrompt` 时按本批片段编号传入。
5. **`ResoundApp`**（`app/src/main/java/app/resound/ResoundApp.kt`）：装配行追加一个命名实参 `playbackMillis = database.transcribe()::playbackMillis`（范围申请 seq=1 已批准）。
6. **`RedoFactory`**（`app/src/main/java/app/resound/redo/RedoFactory.kt`）：重新整理（digest）处传 `db.transcribe().playbackMillis(...)`；合并（merge）处不传，按卡面保持不出外放项。
7. **测试**（`app/src/test/java/app/resound/digest/SituationPrompt130Test.kt`）：保留原有 2 个用例，新增 5 个（阈值边界 3000/2999 且关闭时 lookup 被调用即报错、关闭 + lookup 为空、打开时情境行逐字与 `RULE`/`PLAYBACK_RULE` 共存、全 0 回归逐字节、合并路径传了也不出）。

## 真机需要注意什么

- 本卡数据链路依赖录音服务写的 `segments.playbackMillis`（已存在的列），真机无需迁移；小米 14 Pro 上外放一段视频/播客 ≥ 3 秒后整理，该片段前应出现 `【外放：有】`（开关关）或情境行尾 `外放：来源未知`（开关开）。
- 开关仍是 `includeSituation`（默认关）：不开开关，外放情境行不会出现，但 system 仍会追加 `PLAYBACK_RULE`（提醒大模型别把节目内容当成本人的事）。
- 真机量化基线统计方法：在 sqlite 里查片段表 `SELECT COUNT(*) FROM segments WHERE playbackMillis > 0 AND status != 'SkippedPlayback'`（未跳过且有外放采样的片段数），随机抽 20 条看对应整理产物里有没有假事件/假待办残留；外放但被跳过的片段（`SkippedPlayback`）本卡不整理，不计入。
- Linux 环境无 Xcode，`zsh tools/check_ios.sh` 未跑，需主脑在 Mac 上补跑（本卡动了 `:shared` 的 `SituationPrompt.kt` 与 `TranscribeDao.kt`）。

## 遗留问题

- 第 0 步只有「外放：有 / 来源未知」两档字面，归属（App 名、节目标题）按方案第 3 步另行落地。
- 开关关闭时 system 追加 `PLAYBACK_RULE` 属预期行为（测试 2 锁定）；若负责人希望关开关连规则也不加，需改卡面锁定决策。
