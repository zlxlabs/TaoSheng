# 卡 186c 交付说明：屏幕时间集成：装配、情境行「在用」与遗留修复

## 做了什么

1. **装配（`ResoundApp.kt`）**
   - 事件源提成本地变量 `screenTimeSource`，构造 `ScreenTimeQueries`（`permitted` 与拉取器同源）赋给 `AppGraph.screenTimeReader`。
   - 桌面包名用 `PackageManager` 查 `ACTION_MAIN + CATEGORY_HOME` 全部结果（`MATCH_DEFAULT_ONLY`），再加 `com.android.systemui`。
   - `pushChannels.attachFootprint` 旁加 `pushChannels.attachScreenTime(this, scope)`，接上每日屏幕时间推送。
   - 启动时一次性的 `ScreenTimePullWorker.schedule(...)` 改为在 `scope` 里收集 `screenTimeSettings.enabled`：每次变化调用 `schedule(this, on)`；变为开时另外 `scope.launch` 立即 `puller.pull()` 一次（不等整点）。

2. **情境行「在用」（`SituationPrompt` core + app 包装）**
   - `SituationLookup` 接口新增带默认实现的 `appSessions(from, until): List<NamedAppSession>`（现有实现不用改，已 grep 确认唯一实现是 `SituationStore`，测试匿名对象走默认实现）。
   - `SituationStore` 新增构造参数 `appSessions`（默认空），实现该方法；不受足迹开关约束；`until <= from` 返回空。
   - `LocalSituationLookup.create()` 透传 `{ from, until -> AppGraph.screenTimeReader?.sessions(from, until)?.sessions.orEmpty() }`。
   - 整理时（`transcript`）：`enabled` 且 lookup 非空时整批只调一次 `appSessions(批内最早 startAt, 批内最晚 endAt)`（空批不调）；每个片段取重叠时长最长的一个 App；只对 `playback` Map 的键（手机麦克风片段）出「在用：<名称>」；项顺序固定「当时在｜周围｜在用｜外放」。
   - 本批出现过「在用」项时，`system()` 在 RULE 之后、外放规则之前追加 `IN_USE_RULE`（「不代表负责人在说话内容里提到它」）；没出现时不追加。调用方（`DigestRunner`、`RedoFactory` 重整）都是先 `transcript()` 后 `system()`，批级标记（私有可变字段）因此可行；合并路径（`merge`）不出「在用」，也不追加。
   - app 侧 `SituationPrompt` 包装透出 `IN_USE_RULE` 常量。

3. **遗留修复**
   - **重新打开总开关会补采**：`ScreenTimeSettings` 删除 `onReenabled` 参数，新增必填 `now: () -> Long` 与只读 `val enabledAt`（偏好键 `screenTimeEnabledAt`，默认 0）；从关到开时在同一处写入 `now()`。`ScreenTimePuller.pull()` 起点改为 `max(原四项, settings.enabledAt)`；`coveredUntil < enabledAt` 时在 `commitPull` 之前写一条 `disabled` 缺口 `[coveredUntil, enabledAt)`，提交后覆盖前进，不会重复写。关闭期间的数据不补采。
   - **切换开关不重排任务**：见 1（collect + 立即补拉）。
   - **「A、B(2 秒)、A」重叠计时**：`ScreenTimeRules.sessions` 的同包合并只在输出列表里紧邻（中间没有其他输出段）时进行；穿插了其他包的段不再把中间时间并进自己的段，totals 不再重复计时。
   - **0 点推送空区间**：`loadScreenTimeReport` 中 `until` 不晚于 `from` 时直接返回 null，不调用 reader（否则 `ScreenTimeQueries.sessions` 对空区间抛参数异常）。

## 怎么验证的

- 新增/改写测试 10 个（含卡面必测 1～8 与 E2E）：
  - `SituationPrompt130Test`（app）：mic 片段逐字 `【当时在：家｜在用：微信｜外放：来源未知】`、非 mic 片段无「在用」、整批只查一次 `appSessions`；重叠最长的 App 胜出；打开+无外放+appSessions 空时与 184 逐字相同、关闭时不调 `appSessions`；`IN_USE_RULE` 位置在 RULE 之后外放规则之前；E2E 用真实 `SituationStore`（注入假 `appSessions`）验证 mic/非 mic 分流且恰好查询一次。
  - `ScreenTimePullerTest`（shared）：关→开后拉取起点等于 `enabledAt`、写且只写一条 `disabled` 缺口、覆盖推进后不重复；`setEnabled` 只在关→开时写 `enabledAt`。
  - `ScreenTimeRulesTest`（shared）：A、B(2 秒)、A 不合并且 totals 等于实际亮屏时长；A 暂停 4.9 秒后同页 RESUMED 合并为一段（改写 185a 必测 8 前半）。
  - `ScreenTimePushTest`（app）：`now` 为当天零点（或更早）时 `loadScreenTimeReport` 返回 null 且不调用 reader。
- 全部通过：`:shared:jvmTest`（screentime/digest/context 包）与 `:app:testDebugUnitTest`（digest/screentime/context/push/data/privacy 包，280 个测试）。
- 既有测试同步修改：`reenablingNotifiesOnlyWhenSwitchingFromOff` 改写为 `reenablingWritesEnabledAtOnlyWhenSwitchingFromOff`（`onReenabled` 已删）；`ScreenTimeQueriesTest`、`ScreenTimeMigrationTest`、`RoomPrivacyActionsTest` 三处 `ScreenTimeSettings(...)` 构造调用因 `now` 必填参数机械补 `now = { ... }`（不改断言；范围申请 seq=1 已批准）。
- `zsh tools/check_ios.sh` 跳过：本机 Linux 无 Xcode。

## 真机验收步骤

1. 设置里打开「屏幕时间」总开关，并授予「使用情况访问」权限（设置 → 使用情况访问 → 回响）。
2. 正常用几个 App（微信、浏览器等）几分钟。
3. 问问里问「今天下午用了哪些 App」，应能拿到带显示名的数据。
4. 手动整理一批含手机录音的原话，看情境行出现「在用：<App 名称>」（桌面、系统 UI 不算；外接设备与导入音频的片段不带）。
5. 关掉总开关 1 小时后再打开：问问查看该小时的屏幕数据应为空（关闭期间不补采），缺口里有一条「屏幕时间关闭期间未采集」（`disabled`）。
6. 推送设置里开「每日屏幕时间」（默认 22:00）后点「现在推一次」，确认 webhook 收到 `screen_time` 报文。

## 遗留问题

- 推送设置页的屏幕时间开关由并行卡 188b 做；本卡只接通推送数据链路。
- `disabled` 缺口写在 `commitPull` 之前，若拉取途中事件源抛错，下次拉取会再写一条同样的缺口（与既有 `pull_failed` 缺口同款行为，卡面按「commitPull 之前」锁定，未改）。
- 关闭期间超过系统 10 天保留期时，`pull_failed` 与 `disabled` 两条缺口可能区间重叠，极端场景，未做去重。
- iOS 编译检查需主脑在 Mac 补跑（`:shared` 有改动）。
