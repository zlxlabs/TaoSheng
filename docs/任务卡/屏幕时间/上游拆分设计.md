# 设计说明：按上游作者意见拆分「屏幕时间与外放归属」

出处：上游议题 0xCoach/TaoSheng#41 作者回复（2026-11-15），负责人确认「全部照办」。
现状调研：调研卡 194 报告（只读，82 个文件逐项归类）。

## 目标

上游先收到一个能独立合并的 PR-A「播放检测 + 外放归属」：
- 不开任何权限，外放片段的整理就能标出「手机在外放」，不会再被当成「我」的经历；
- 用户可以自己打开「记录播放标题」，标注里会带上 App 和节目名；
- 外放片段由用户决定只转写，还是转写并参与整理。

PR-A 合入后，再提 PR-B「屏幕时间采集 + 每日推送 + 今日卡片 + 问问 apps_during」。

## 非目标

- 不实现蓝牙麦克风自动让路（作者之后自己做）；只提供「现在是否在播放」的订阅入口。
- 不改数据库编号，不回填历史片段：新开关只影响打开之后录下的片段。
- 不精修界面，作者合入后统一风格。
- 不在上游议题回复；开 PR 时在描述里逐条对应作者意见。

## 为什么不是分区 / 删除 / 约定

- **分区**：播放检测分两层。基础层（是否在放、是否走扬声器）由上游已有的 `PlaybackMonitor` 负责；标题层（哪个 App、什么节目）由通知监听负责。两层各有自己的开关和数据，互不依赖。
- **删除**：PR-A 去掉一切依赖屏幕时间采集的能力：「在用 App」情境行、`apps_during`、外放标注拿前台 App 兜底。这些放到 PR-B，PR-A 不需要为「屏幕时间没开」写特例。
- **约定**：数据库沿用已定的 35→37 三步迁移，五张表的结构全部在 PR-A 一次带齐（屏幕时间的四张表在 PR-A 中是空表）。不为拆分改动迁移内容。

## 方案要点

### 1. 数据库（PR-A 一次带齐）
34→35、35→36、36→37 三步迁移、35/36/37 schema、五张表的实体、隐私删除与备份分类原样进 PR-A；PR-B 不再升库。理由：播放断连缺口写在 34→35 建的 `screen_coverage_gaps` 表；改迁移内容就得重新导出 schema，还会和作者「编号保持原样」冲突。

### 2. 播放状态订阅（作者第 2 条，基础层）
- `:shared` 新增共用数据类 `PlaybackState(playing: Boolean, speakerPlaying: Boolean)`。`playing` 表示任何媒体在放，含耳机和蓝牙；`speakerPlaying` 表示在放且走扬声器，即现有外放判定。
- `PlaybackMonitor` 对外提供 `StateFlow<PlaybackState>`，并主动刷新：系统回调触发重算，播放中按现有 500 毫秒间隔轮询，停播后发布 false，取消时注销回调。不能只给懒刷新的 getter 包一层。
- 由 `AppGraph` 在应用级持有一份；`CaptureService` 改为订阅它，录音输入侧以后也可以订阅。外放判定规则（半段阈值、耳机排除）不变，`PlaybackPolicyTest` 继续有效。
- 基础层没有开关，始终开启；它不落库，只供录音切段和以后的让路使用。

### 3. 标题层（作者第 2 条）
- 新增用户设置「记录播放标题」，默认关，与屏幕时间开关无关。`PlaybackRecorder` 改由它门控。
- 关闭时不写播放记录；打开时立即把当前正在播放的会话补记为开始，不必等下一首。系统通知使用权被撤销时保留已有历史，并记一段缺口。
- 位置：「原话与转写」页外放区域，和「外放声音时不转写」放在一起。打开后若没有通知使用权，就引导去开启。

### 4. 外放标注文案
- 片段外放时长达到阈值时：
  - 标题层开、且隐私开关开、能匹配到播放记录 → `外放：可能是 某App《标题》`，或 `外放：可能是 某App`；
  - 其余情况一律写 `外放：手机在外放`。
- 删掉「来源未知」和「拿前台 App 兜底」两种文案。

### 5. 隐私开关（作者第 3 条）
- 新增「整理时带上 App 与播放信息」，默认开，独立于现有「附带情境」开关；「附带情境」默认关，只管地点和环境，行为不变。
- 管住所有对外发送 App 或节目名的地方：普通整理、重新整理，以及 PR-B 的 `apps_during`。关闭时连查询都不做，工具执行前直接拒绝。
- 基础的「手机在外放」不受它管，这条事实不含 App 或节目信息。
- 位置：最终放在屏幕时间页底部，屏幕时间和播放标题都没开时不显示。PR-A 还没有屏幕时间页，暂时放在「记录播放标题」下方，只在标题层开启时显示；PR-B 再搬到屏幕时间页底部。合并后的最终位置符合作者的表格。

### 6. 外放片段进不进整理（作者第 4 条）
- 「外放片段」的判定与「外放声音时不转写」相同：外放占片段一半以上。
- 被跳过转写的外放片段，按钮改为「只转写」和「转写并整理」二选一。一次操作同时写入转写状态和整理意图（`playbackDigest`：1 表示暂不整理，2 表示参与整理），中间不留被自动整理抢先的空档。
- 新增整体开关「外放内容也参与整理」，默认关，放在「外放声音时不转写」下面。它决定自动进入转写的外放片段的初始意图：关时记 1，开时记 2。「外放声音时不转写」关闭时，外放片段会自动转写，这个开关仍然生效。
- 已经转写、仍处于「暂不整理」的片段，保留现有的「参与整理」补救入口。
- 只作用于新片段，旧数据的 `playbackDigest` 保持 0，不回填。
- 用户手动发起的重新整理不受这个过滤影响，视为用户主动覆盖。

### 7. 设置备份分类（上游卡 190 规则）
「记录播放标题」「外放内容也参与整理」「整理时带上 App 与播放信息」都是用户选择，进备份。以下属于本机状态，不进备份：通知使用权、运行中的播放状态、会话标识。

## 已否决方案

- **PR-A 只带 35→36、36→37 两步迁移，或把 34→35 改成空迁移**：从上游 34 升不上去，或者丢掉缺口表。
- **改各步迁移的内容，让 PR-A 只建播放相关的表**：要重新导出 schema，PR-B 还得升到 38，和作者「编号保持原样」冲突。
- **PR-A 就带 `apps_during`，只返回播放段**：同一个工具契约要在两个 PR 里各改一次，评审面更大。
- **在 PR-A 做一个空壳屏幕时间页，只为放隐私开关**：用户看到「屏幕时间」入口点进去却没有屏幕时间功能，会困惑。
- **新隐私开关直接复用「附带情境」**：两者默认值相反，复用必然改错其中一方的行为。

## 关键不变式（实现卡验收时逐条对上测试）

1. 基础层：不开任何权限时外放标注照常出现；暂停播放后订阅流会主动发布 false。由 A2 卡的单测锁定。
2. 标题层关时，播放记录零写入，提示词里不出现 App 或节目名。由 A1 卡锁定。
3. 隐私开关关时，普通整理和重新整理的提示词都不含 App 或节目名。由 A3 卡锁定。
4. 「只转写」「转写并整理」一次写入，结果分别是 `playbackDigest` 为 1 和 2；整体开关开或关时，新的自动转写外放片段分别记 2 和 1；普通片段保持 0。由 A3 卡锁定。
5. 从 34 一路升到 `CaptureDatabase.VERSION` 的结果与新装库的 schema 一致，沿用现有 index183 快照契约。由 A1 卡锁定。

## 验收路径

1. 入口：测试机装 PR-A 构建，不开通知使用权。
2. 步骤：外放播客录一段，选「只转写」；再录一段，选「转写并整理」。然后打开「记录播放标题」并授权，再外放一段，最后触发整理。
3. 预期：
   - 选「只转写」的片段不进事件；
   - 选「转写并整理」的片段进事件，并标注「手机在外放」；
   - 授权后录的片段标注 `外放：可能是 某App《标题》`；
   - 关掉隐私开关后再整理，标注回到「手机在外放」。
