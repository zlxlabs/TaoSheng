# 卡 190a 交付说明：设备播放记录数据层

## 做了什么

- 新表 `playback_rows`（`PlaybackRow`）：按 `fromAt`、`sessionKey` 建索引；`name` 是写入时的 App 名快照，查不到等于 `pkg`；播放中 `untilAt` 为 null。不存「是否外放」。
- 数据库 `CaptureDatabase.VERSION` 35→36，仅在 `MIGRATIONS` 末尾登记 `MIGRATION_35_36`。建表 SQL 与实体 `createSql` 对齐。导出 `shared/schemas/app.resound.data.CaptureDatabase/36.json`（identityHash `4324ee42f6c776d1a0ad6e36590e98fc`）。
- `ScreenTimeDao` 增加播放行的读写、重叠查询（有效终点 `COALESCE(untilAt, lastSeenAt)`）、断开缺口闭合，以及隐私删除事务 `forgetPlayback`（区内整行删除、跨左边界含双侧只留左半段、跨右边界把起点挪到 `until`）。
- 新建 `PlaybackRecorder`：实现 `PlaybackSink`。四个方法共用一把 `Mutex`；总开关关闭时全部直接返回、不写库。开关重新打开后、做其他事之前，先把 `lastSeenAt < enabledAt` 的未结束行收尾在各自 `lastSeenAt`（不另写缺口），避免关闭期间被续成连续播放。标题变化切行、空标题补写不切行、心跳只刷新 `lastSeenAt`、`disconnected` 收尾在 `lastSeenAt` 并写仍断开的 `listener_disconnected` 缺口、`connected` 先闭合 `untilAt=MAX` 的缺口，若没有缺口但还有未结束行则按进程被杀补 `[max(lastSeenAt), at)`，再把未结束行收尾。空白标题 trim 后当 null。
- `ScreenTimeQueries` 新增必填 `playbackPermitted`。总开关关闭仍返回 `DISABLED`。开启时补 `devicePlayback`（裁到查询区间、长度为 0 丢掉、按 `from` 升序、标题脱敏、null 保持 null）和 playback 缺口（until 裁到 `now()`）；无通知使用权时历史行照常返回，并追加 `notification_access_missing`。不另触发播放拉取。
- 隐私删除：与现有 `deleteEvents` 同一事务里调用 `forgetPlayback`。
- 备份：`playback_rows` 按 `fromAt` 登记为按天表。
- 装配：`AppGraph.playbackSink = PlaybackRecorder(...)`；查询传入 `NotificationManagerCompat.getEnabledListenerPackages` 是否含本包名。
- 卡 183 冻结夹具：`expected-delta.json` 按 185c 同一写法逐行登记 36 版差异（版本行、身份哈希、两个新索引、新表及空表数据块）。旧 34/35 行全部保留。`Index183ComparatorTest` 的「错版本」反例改为相对 `CaptureDatabase.VERSION`。仓内无 `index185/` 目录，未新建。

`PlaybackRecorder` 构造函数已锁死、没有日志回调；本类不记标题。落库失败 fail fast，由卡 190b 调用方记 `playback:` 前缀日志。

## 真机验收步骤

监听服务由卡 190b 接入。本卡数据层就绪后，负责人在真机：

1. 打开屏幕时间总开关，并授予通知使用权。
2. 用小宇宙播放任意节目约 2 分钟后暂停。
3. root 查 `playback_rows`：应有一行，`pkg` 为小宇宙、`fromAt` 在按下播放附近、`untilAt` 在暂停附近（或仍为 null 且 `lastSeenAt` 接近暂停），`title` 为当时节目标题快照。
4. 不要用这条记录当「本人在听」；本表只表示手机在播放。

## 遗留问题

- 卡 190b 才把通知监听接到 `AppGraph.playbackSink`；在此之前真机不会写入 `playback_rows`。
- `36.json` 是 Room 全量导出（约 3100 行），会使本卡 diff 超过卡面硬顶 900 行；这是导出 schema 的必要产物，不是顺手扩写。
- 无通知使用权时，已落库的播放行和 playback 缺口仍返回（按数据源分别处理授权）；界面如何提示归 190d。
