# 185a 交付说明：屏幕时间计算规则（纯函数，:shared）

## 做了什么

在 `:shared` 新建 `app.resound.screentime` 包，三个文件：

- `shared/src/commonMain/kotlin/app/resound/screentime/ScreenTimeModel.kt`：卡面锁定决策的数据模型——`ScreenEventType`（9 个事件类型，code 即 Android `UsageEvents.Event` 常量，伴生 `of()` 未知码返回 null）、`ScreenEvent`、`AppSession`（左闭右开）、`AppTotal`、`ScreenTimeConfig`。字段名与卡面逐一核对一致，未增删。
- `shared/src/commonMain/kotlin/app/resound/screentime/ScreenTimeRules.kt`：`object ScreenTimeRules` 三个纯函数——`sessions()`（事件重放状态机）、`totals()`（按包聚合，时长降序/包名升序）、`dayTotals()`（按 `kotlinx.datetime.TimeZone` 自然日聚合，跨零点拆两天）。平台无关：只依赖 `kotlinx.datetime`，无 `android.*`/`java.*`。
- `shared/src/jvmTest/kotlin/app/resound/screentime/ScreenTimeRulesTest.kt`：13 个用例，覆盖卡面必测 1～10 加上 `of()` 白名单与 `totals` 排序。

### 状态机实现要点（卡面 8 条语义的落点）

1. 排序键 `(at, id)`：`compareBy({ it.at }, { it.id })`，同一毫秒事件顺序稳定（测试 9）。
2. 「当前前台页面」为 `(pkg, cls)` 二元组；PAUSED/STOPPED 只在页面恰好等于前台页面时收尾，同 App 切页时旧页 STOPPED 被忽略（测试 1）。
3. 熄屏/锁屏收尾但保留前台；KEYGUARD_HIDDEN 解锁、SCREEN_ON 未锁屏亮屏时为保留的前台从该时刻重新开段（解锁续接，测试 3）。锁屏期间的 RESUMED 只更新前台不开段。
4. SHUTDOWN/STARTUP 收尾并清空前台、复位亮屏未锁屏（测试 4）。
5. 重放结束仍开着的段截止于 `min(until, coveredUntil)`（测试 5）；起点前已开着的段裁剪到 `from`（测试 6）。
6. excluded 包名的 RESUMED 照样收尾上一段、自身不输出（测试 7）。
7. 合并：同包上一段因「切换」收尾（非熄屏/锁屏/关机）且间隔 ≤ `mergeGapMillis`（5 秒）时合并；合并段继承最后并入段的收尾原因，链式合并正确（测试 8a/8b）。

### 两处卡面歧义的处理（供主脑复核）

- **SCREEN_ON 的熄屏解除**：卡面写「`SCREEN_ON` 且未锁屏：解除熄屏」，字面可读成「锁屏挂着时不解除熄屏」。实现取「SCREEN_ON 一律解除熄屏，仅未锁屏时重开段」：锁屏期间屏幕物理上是亮的，不解除会让状态与现实不一致，后续 KEYGUARD_HIDDEN 逻辑不受影响（KEYGUARD_HIDDEN 不检查 screenOn，按卡面字面）。
- **「同包相邻段」**：测试 8a 中 B 的极短段夹在 A 两段之间，若按「列表里紧邻的两段」解释则 A 永远无法合并，与测试期望矛盾。实现取「该包输出序列中的上一段」（中间可隔其他包的段）；被合并段的间隔计算用合并后的边界。B 的极短段独立保留在输出里。

## 真机需要注意什么

- 本卡为纯函数，无真机路径；真机观察（同 App 换页每对 PAUSED/RESUMED、熄屏与 PAUSED 同秒、锁屏下 RESUMED 直到 KEYGUARD_HIDDEN 可见）已编入测试事件向量。
- 卡 185b 存原始事件时须存 Android 常量整数（`RESUMED=1` 等），系统级事件 pkg/cls 存空串；`ScreenEventType.of()` 会拒绝白名单外的码（如 `ACTIVITY_FOREGROUND_SERVICE=19`、`NOTIFICATION_SEEN=12`），185b 不需要为这些码改模型。

## 遗留问题

- 本机为 Linux 无 Xcode，`zsh tools/check_ios.sh` 跳过，**主脑需在 Mac 补跑**（改了 `:shared` 共用代码，按仓库约定需 iOS 编译检查）。
- 合并产生的重叠：A 两段合并抹平抖动后，中间 B 的极短段与合并后的 A 段在时间上重叠；总时长聚合时会有与抖动等长（≤5 秒）的重复计数，属设计内行为，卡 186 若需要精确去重可在聚合层处理。
- `ScreenTimeConfig` 的 `titleMaxCodePoints`/`heartbeatMillis`/`pullThrottleMillis`/`topApps` 本卡未消费，是卡面锁定决策的字段，供 185b/186 使用。
