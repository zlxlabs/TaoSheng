# 卡 186d 交付说明：屏幕时间真机验收修复（设置被误排除、关闭前数据丢失、缺口重复、文案名称）

## 做了什么

1. **「设置」不再被当桌面排除（`ResoundApp.kt`）**
   - 桌面排除集合从「HOME intent 的全部解析结果」改为「其中 `ResolveInfo.priority >= 0` 的项」再加 `com.android.systemui`。
   - 原因：系统设置的后备桌面 `com.android.settings/.FallbackHome` 以 priority = -1000 兜底响应 HOME，按包名收集会把整个 `com.android.settings` 排除掉，导致设置页的使用时间统计不到。正规桌面（如小米桌面 `com.miui.home/.launcher.Launcher`，priority = 0）不受影响。

2. **关闭总开关不再丢关闭前的数据（`ScreenTimeSettings.kt` + `ScreenTimePuller.kt`）**
   - `ScreenTimeSettings` 新增只读 `val disabledAt: Long`（偏好键 `screenTimeDisabledAt`，默认 0，从未关闭为 0）；从开到关时在保存开关的同一处写 `now()`（写失败抛异常，与 `enabledAt` 同款 `check`）。从关到开仍写 `enabledAt`，不动 `disabledAt`。
   - 拉取起点（Mutex 内）：`state == null`（从未提交过）保持原行为 `max(原四项, enabledAt)`，第一次打开不补采历史；`state != null` 时起点去掉 `enabledAt` 项，为 `max(lastEventAt, coveredUntil, floor, horizon)`——从上次采集到关开关之间、开关仍开着的那段使用记录照常补拉入库（真机实测原来丢约 28 秒，就是这段）。

3. **关闭期间缺口与残留事件的口径（`ScreenTimePuller.kt`）**
   - 设 `offFrom = max(coveredUntil, disabledAt)`。`coveredUntil < enabledAt` 且 `disabledAt > 0` 且 `offFrom < enabledAt` 时：缺口为 `disabled [offFrom, enabledAt)`，并从事件源取回的事件里丢掉 `at ∈ [offFrom, enabledAt)` 的关闭期间残留事件。
   - `coveredUntil < enabledAt` 但 `disabledAt == 0`（升级用户：186c 时期关过、没有关闭时刻）：沿用 186c 行为，起点圈到 `enabledAt`，缺口 `disabled [coveredUntil, enabledAt)`。
   - `pull_failed`（超出系统保留期）缺口逻辑不变。

4. **缺口不重复写（`ScreenTimeDao.kt` + `ScreenTimePuller.kt`）**
   - `commitPull` 新增必填参数 `gaps: List<ScreenCoverageGapRow>`，缺口与事件、名称、覆盖指针在同一 `@Transaction` 内写入（默认实现里循环调用保留的 `recordGap`，未新增 DAO 方法）。
   - `ScreenTimePuller` 不再在 `source.since` 之前调 `recordGap`，改为把缺口收集成列表传给 `commitPull`：事件源抛错时缺口与覆盖指针一起不落库，下次拉取重新计算，不再出现「缺口已落库、进度没前进」导致的重复缺口。

5. **屏幕时间页文案（`ScreenTimePage.kt`）**
   - 说明文字里写死的「回响」改为 `"打开后，" + stringResource(R.string.app_name) + "每小时……"`，App 名（「涛声」）随资源走，其余字句不变。

## 怎么验证的

- 先写必测 1～4（红：新增测试引用的 `DISABLED_AT_KEY`、4 参 `commitPull` 在 base 上不存在，编译失败即不可能通过），再实现，红转绿：
  - 必测 1 关闭前数据保留：`eventsBeforeSwitchOffAreKeptAndDisabledGapStartsAtDisabledAt`——T0 已覆盖、T1 事件、T2 关、T3 事件（关闭期间）、T4 开、T5 事件；拉取保留 T1、T5 丢弃 T3，只写一条 `disabled [T2, T4)`。
  - 必测 2 第一次打开：`firstPullAfterEnableStartsAtEnabledAtAndWritesNoGap`——`state == null` 时起点正好 `enabledAt`、不写任何缺口。
  - 必测 3 升级兼容：186c「重新打开」测试按新语义改写为 `legacyReopenWithoutDisabledAtKeeps186cBehavior`（`disabledAt == 0` 且上次覆盖早于本次打开 → 起点圈到 `enabledAt`，缺口 `[上次覆盖, enabledAt)`，覆盖推进后不重复），未新增变体。
  - 必测 4 缺口不重复：`gapIsNotWrittenWhenSourceThrowsAndCommitsOnceOnSuccess`——事件源在 `since` 抛错时 0 缺口、覆盖进度不变；随后一次成功拉取只写一条。
  - `reenablingWritesEnabledAtOnlyWhenSwitchingFromOff` 扩展断言：开→关写 `disabledAt`、已关再关不重写、关→开不动 `disabledAt`、从未关闭为 0。
- Accept-Check 全过（exit 0）：`:shared:check`、`python3 tools/check_shared.py`、`:shared:jvmTest --tests 'app.resound.screentime.*'`、`:app:testDebugUnitTest --tests 'app.resound.screentime.*' --tests 'app.resound.privacy.*'`、`:app:assembleDebug`（compileDebugKotlin 随之完成）。
- `zsh tools/check_ios.sh` 跳过：本机 Linux 无 Xcode（改动涉及 `:shared` 共用代码，CI 有 iOS 编译检查兜底）。
- `RoomPrivacyActionsTest` 用真 Room 库、`ScreenTimeQueriesTest`/`ScreenTimeMigrationTest` 走接口默认实现，均无需改动即随签名通过。

## 真机验收步骤（小米 14 Pro，HyperOS 3）

1. **设置不再被误排除**：打开「屏幕时间」总开关并授予使用情况访问权限，在系统「设置」里停留约 20 秒，回到 App 用问问问「刚才在用什么」，应能看到「设置」入列；同时确认桌面（小米桌面）本身仍不入列。
2. **关闭前数据不丢**：开着总开关正常用手机几分钟 → 关掉总开关 → 等 1 分钟 → 重新打开 → 触发一次采集（打开开关会立即补拉一次）后问问问「关开关前那几分钟在用什么」，关闭前的使用应仍在；屏幕时间页的缺口条应只覆盖真正关闭的那一小段。
3. **文案**：设置 → 屏幕时间页的说明文字应显示「打开后，涛声每小时……」。

- 输入法、权限控制器等系统界面算不算「在用」：真机已见「豆包输入法」「权限控制器」入列，本卡不处理，留待观察。
- 查询缺口文案里仍有「回响」字样（`ScreenTimeQueries.kt` 的 `USAGE_ACCESS_MISSING`/`COVERAGE_LAG` 修复提示）：这段在 `:shared` 平台无关代码里，拿不到安卓字符串资源，超出本卡边界（本卡只改屏幕时间页说明一处），如需统一改名要走单独的卡。
- 缺口条带时间轴（`coverage_lag` 现算）与重叠缺口的展示口径未动。
