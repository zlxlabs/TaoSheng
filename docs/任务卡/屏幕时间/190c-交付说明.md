# 卡 190c 交付说明：设备播放记录的出口与外放归属

## 做了什么

把约定里已有的 `devicePlayback` 接到四个出口。数据层仍由 190a 负责，本卡测试一律用假 `SituationLookup` 和手工构造的 `ScreenTimeResult`。

1. **情境行外放归属**（`SituationPrompt.kt`，只改 `enabled && lookup != null` 这一支）
   - 整批 `appSessions` 仍只查一次。本批存在外放片段时再查一次 `devicePlayback`；没有外放片段不查。
   - 对正在外放的组，按顺序取：重叠最长的播放记录（有标题 `外放：可能是 名《标题》`，无标题 `外放：可能是 名`）→ 否则落到在用 App → 否则 `外放：来源未知`。
   - `name` / `title` 再过一次 `singleLine`。在用项与「外放：可能是 同一 App」同时成立时两项都出。关闭支仍是 `【外放：有】`，`PLAYBACK_RULE` 未改。

2. **安卓透传**
   - `SituationStore` 增加 `devicePlayback` 构造参数，默认 `{ _, _ -> emptyList() }`，与 `appSessions` 同款。
   - `LocalSituationLookup.create()` 补上 `AppGraph.screenTimeReader?.sessions(from, until)?.devicePlayback.orEmpty()`。

3. **问问 `apps_during`**
   - `devicePlayback` 每项为 `ref, name, package, title, subtitle, start, end`；null 写 JSON null；时间用 `AskTime.format`；按 `from` 升序。
   - 每项登记 `AskSource("playback", …)`，与 sessions 共用出处编号。
   - 6000 字符预算：totals 完整，再 sessions，再 devicePlayback；超预算撤掉该项并停止后续。
   - 工具描述改为含「设备播放记录，只表示手机在播放，不代表本人在听」。

4. **推送 Webhook 与报告**
   - `screenTimePayload` 按 `package, name, title, subtitle, start, end` 写出非空 `devicePlayback`。
   - `ScreenTimeReports.build` 按 `(name, title)` 分组、时长降序再按 name 升序、取前 `topApps`；有内容时 body 在 App 行之后、缺口行之前插入「设备播放记录：」，markdown 另起一段并加免责声明；没有播放记录时与现在逐字相同。

## 真机验收步骤

联调在 190a/190b 合并后由主脑真机验收：

1. 打开屏幕时间总开关，授予使用情况访问和通知使用权。
2. 用小宇宙外放一集，同时用手机麦克风录音并整理。
3. 情境行应出现 `外放：可能是 小宇宙《…》`（节目标题以系统通知为准）。
4. 问问「刚才手机在放什么」，`apps_during` 的 `devicePlayback` 应非空。
5. 推一次屏幕时间 Webhook，JSON 里 `devicePlayback` 非空，订阅文档「## 屏幕时间」下有「设备播放记录」一段。

## 遗留问题

- 预查询模式（`AskMode.Prefetch`）不覆盖屏幕时间问题：程序先查的路径不会调 `apps_during`，追问时 `kind = "playback"` 与 `kind = "screen"` 一样不能经 `refresh` 核验，必须再调一次工具。
- 透传会为 `appSessions` 和 `devicePlayback` 各调一次 `screenTimeReader.sessions`（仿照 186c 现有写法，未合并）。
- iOS 编译检查需主脑在 Mac 补跑。
