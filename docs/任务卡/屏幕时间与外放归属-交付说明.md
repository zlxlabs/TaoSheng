# 屏幕时间与外放归属

把屏幕时间采集、设备播放记录和外放归属接到整理、问问、推送和今日页。默认关闭；打开后数据只存在本机。

## 功能

- **采集**：总开关打开后，每小时从系统使用情况读取 App 前台事件，合成使用段和每日合计。桌面和系统 UI 不算「在用」。关闭后不再拉取，已有数据保留，但问问、推送和整理都不再用。
- **设备播放记录**：在通知使用权打开时记下手机正在播放什么（App、节目标题、起止）。只表示手机在播，不代表本人在听；不读通知正文。
- **整理标注**：麦克风片段会带当时在用的 App；若这段有外放（扬声器播放满 3 秒），按播放记录或在用 App 标出外放提示，提醒模型不要把节目里的话当成负责人说的。
- **整段外放暂不整理**：系统判成外放、用户仍要转写的片段会转写，但先不进整理；原话页可放行，下一轮整理再处理。
- **问问**：工具 `apps_during` 按时间段返回用过的 App、时长和设备播放记录。总开关关闭时没有数据。
- **每日屏幕时间推送**：推送通道可订阅「每日屏幕时间」，到点发送当天合计（默认只发 App 名和时长）。
- **今日卡片**：今日页展示当天屏幕时间，可打开详情。

## 两项系统权限

1. **使用情况访问**（`PACKAGE_USAGE_STATS`）：读 App 前台使用。设置页在打开总开关后引导去系统页开启。
2. **通知使用权**（通知监听服务）：可选，用于设备播放记录和外放归属。不开启时仍可记屏幕时间，外放归属会退回「当时在用的 App」。

两处都在「设置 → 屏幕时间」里显示当前状态，并提供「去开启」。

## 数据库 34→37

- **34→35**：四张屏幕时间表：`screen_events`、`screen_app_names`、`screen_pull_state`、`screen_coverage_gaps`。事件按 `(at,pkg,type,cls)` 唯一，重复拉取靠冲突忽略去重。
- **35→36**：`playback_rows` 设备播放记录；进行中的播放 `untilAt` 为空。
- **36→37**：`segments.playbackDigest`（0 正常，1 暂不整理，2 已放行）。

当前 `CaptureDatabase.VERSION = 37`。迁移挂在 `CaptureDatabase.MIGRATIONS` 上；升到最新版本的测试断言用 `CaptureDatabase.VERSION`。

备份分卷：`screen_events`、`playback_rows` 按天；`screen_app_names`、`screen_pull_state`、`screen_coverage_gaps` 进状态卷。恢复后覆盖指针以表内实际事件为准。

设置文件 `screen-time`：总开关和开/关时刻随设置备份；上次拉取时间是本机节流，不备份。推送里的「今天已发屏幕时间」跟其他发送游标一样，不进备份。

## 隐私

- 数据只存在本机数据库，不上传。
- 总开关默认关；关掉后不再采集。已写入的记录不会自动删。
- 隐私删除（按时间遗忘）会删对应区间的屏幕事件和播放记录，并把拉取下限提到区间终点，避免之后再被系统拉回来。
- 问问、推送、整理只用显示名，不把 Activity 类名对外发出。

## 怎么验证

电脑上：

```
python3 tools/check_shared.py
./gradlew -PskipSigningSecrets=true :shared:check -q
./gradlew -PskipSigningSecrets=true :app:testDebugUnitTest \
  --tests 'app.resound.screentime.*' --tests 'app.resound.data.*' \
  --tests 'app.resound.push.*' --tests 'app.resound.transcribe.*' \
  --tests 'app.resound.digest.*' --tests 'app.resound.privacy.*' \
  --tests 'app.resound.backup.*'
./gradlew -PskipSigningSecrets=true :app:assembleDebug -q
```

覆盖：34→37 迁移、使用段规则、拉取与缺口、问问 `apps_during`、整理情境行「在用」与外放三档归属、外放暂不整理/放行、每日屏幕时间推送、设置备份把总开关带上且不带上次拉取时间、按时间遗忘清屏幕数据。

## 真机注意事项

- 目标机：小米 14 Pro（澎湃 OS）。使用情况访问、通知使用权都是系统特殊权限，应用里只能跳转，不能代开。
- 打开总开关后应立刻出现「去开启」使用情况访问；未开权限时不拉取，问问会说明原因。
- 通知使用权是可选的。没开时没有设备播放记录，整理仍可能标「外放」，归属落到当时在用的 App。
- 系统「数字健康」的总时长和这里不会逐分钟一致：这里排除桌面和系统 UI，且只在开关打开期间采集。
- 需要看的界面：设置 → 屏幕时间；今日页卡片和详情；原话页「外放 · 不参与整理」与放行；推送通道里的每日屏幕时间开关。
- 本机没有 Xcode，未跑 iOS 编译检查。
