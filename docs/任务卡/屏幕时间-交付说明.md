# 屏幕时间采集、读取与问问

在「设备播放记录 + 外放归属」之上接回屏幕时间的非界面、非推送部分：UsageStats 增量采集、日报渲染、整理提示词里的「在用 App」，以及问问工具 `apps_during`。播放检测、外放标注和「记录播放标题」开关维持上一份交付，本卡不改它们的写入或读取门控。

## 功能

- **屏幕时间采集**（默认关）：独立于「记录播放标题」。打开后按使用情况访问权限增量拉取 UsageStats 事件，每小时补拉一次；关闭期间不补采，只记缺口。拉取进度（上次成功时刻）不进设置备份。
- **读取与日报**：`ScreenTimeQueries` 实现 `ScreenTimeReader`，查询前先增量拉取；需要播放段时调用 `PlaybackQueries`，不复制查询。`ScreenTimeReports.build` 把使用段、设备播放记录和缺口渲成日报正文/Markdown。
- **「在用 App」情境行**：只有屏幕时间采集开 **且** 「整理时带上 App 与播放信息」开时才查前台使用段；否则不查库、提示词没有「在用」行。它不受「整理时参考地点和环境音」影响。外放标注仍是上一份的三档（有标题 / 有 App / 「手机在外放」），不用前台 App 兜底。
- **问问 `apps_during`**：隐私开关关闭或屏幕时间采集关闭时，查库前直接返回说明，不读事件表。结果里的播放段只有「记录播放标题」开且隐私开关开时才出现。工具定义与返回 JSON 按实际序列化文本验收。

## 隐私开关管辖范围

「整理时带上 App 与播放信息」（`DigestPreferenceStore.includeAppPlayback`，默认开）是对外发送 App 名或节目名的唯一闸，出口收在 `AppPlaybackPrompt`：

| 出口 | 还要同时开 | 关闭时 |
|---|---|---|
| 整理/重整提示词「在用」 | 屏幕时间采集 | 不查前台使用段，没有「在用」行 |
| 整理/重整提示词播放标题 | 记录播放标题 | 不查播放记录，外放只标「手机在外放」 |
| 问问 `apps_during` | 屏幕时间采集 | 查库前返回「用户关闭了整理时带上 App 与播放信息」或「屏幕时间未开启」 |

本机日报、数据库和备份里的屏幕事件不受此闸影响。采集开关和开/关时刻进设置备份；`screenTimeLastPullAt` 不进备份。

## 怎么验证

电脑：

```
python3 tools/check_shared.py
./gradlew :shared:check
./gradlew :app:testDebugUnitTest --tests 'app.resound.screentime.*' --tests 'app.resound.data.*' --tests 'app.resound.digest.*' --tests 'app.resound.privacy.*' --tests 'app.resound.backup.*' --tests 'app.resound.ask.*'
./gradlew :app:assembleDebug
```

本卡新增/恢复的单测覆盖：采集规则与拉取器、日报渲染、问问 JSON、隐私关闭不查库、提示词没有「在用」、屏幕采集关时播放标题仍写入。

## 真机注意事项

- 打开屏幕时间采集后，系统设置里还要给回响「使用情况访问」权限，否则历史能读、新事件拉不进来，查询会带 `usage_access_missing` 缺口。
- 「记录播放标题」仍要通知使用权；与屏幕采集互不影响。
- 界面入口、今日卡片和每日推送尚未接上，本机验证采集是否在跑可看数据库 `screen_events` / `screen_pull_state`，或等后续界面卡。
- Linux 开发机没有 Xcode，iOS 编译检查未跑。
