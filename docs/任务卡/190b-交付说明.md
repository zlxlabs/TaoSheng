# 卡 190b 交付说明：通知监听服务（把媒体会话变化报给 PlaybackSink）

## 做了什么

正式版新增 `PlaybackListenerService`（`NotificationListenerService`），只为取得 `MediaSessionManager.getActiveSessions` 授权，不读、不记通知内容，也不覆写 `onNotificationPosted` / `onNotificationRemoved`。

连上后把当前媒体会话注册回调，播放/暂停/标题变化、会话消失、心跳都经 `AppGraph.playbackSink` 串行上报。本卡分支上 sink 尚未装配（卡 190a），回调在服务内直接丢弃；本卡只验编译。

## 怎么验证的

- `./gradlew -PskipSigningSecrets=true --no-daemon --max-workers=2 :app:assembleDebug -q` → exit 0（约 252s；同机其他卡在编译，限并发避免 OOM）
- `./gradlew -PskipSigningSecrets=true --no-daemon --max-workers=2 :app:assembleRelease -q` → exit 0（约 299s，在 debug 之后串行跑）
- `python3 …/card_scope_check.py --card <本派发卡面> --repo . --commit-range e2bc1db4126b9165e6096ec8f3cf54b144384558..HEAD` → 通过（3 个变更文件均在 Scope-Globs）。卡面写的 `--range` 旧入口会拿 main-tip 当锚，把 Base 约定提交里的 `AppGraph.kt` / `ScreenTimeContract.kt` 误判越界；执行器范围用 `--commit-range`。
- 不写单元测试（平台服务，真机验收）。

## 授权命令

```
adb shell cmd notification allow_listener app.resound/app.resound.screentime.PlaybackListenerService
```

撤销：`adb shell cmd notification disallow_listener app.resound/app.resound.screentime.PlaybackListenerService`

## 看日志命令

```
adb logcat -s playback
```

只记事件种类和会话数，不记标题：`connected` / `sessions-changed` / `heartbeat` / `disconnected`。sink 异常一行 `playback: <异常类名>`。

## 真机验收步骤

目标机：小米 14 Pro（澎湃 OS）。主脑合并 190a 后：

1. 升级安装，执行上面的授权命令（或在系统设置里打开回响的通知使用权）。
2. `adb logcat -s playback`，应看到 `playback: connected sessions=N`。
3. 打开小宇宙播放：`sessions-changed` 或已有会话的状态回调；暂停后再播，回调应实时到达。
4. 保持播放超过 60 秒：出现 `playback: heartbeat n≥1`。
5. 查 `playback_rows`：播放开行、暂停收尾、心跳刷新最后观测时刻。
6. 熄屏一段时间后继续播/停，服务仍在、回调仍到（卡 189 已在本机验证 2 小时深度省电）。

本卡单独装包时 sink 为 null，第 5 步无行；只验第 2～4 步的 logcat。

## 心跳判定的简化及理由

eng 块「播放记录不凭空延长」要求比较 `position` 与 `lastPositionUpdateTime`。真机上很多 App 播放中不刷新 `lastPositionUpdateTime`，按它判定会把正常长播放截断。本卡改为：`state == STATE_PLAYING` 且 `playbackSpeed > 0f` 才心跳。暂停、速度为 0 的「播放中」不刷新最后观测时刻。
